## 核心觀念
RAG = Retrieval-Augmented Generation。文件切塊（Chunking）→ 建立索引（Keyword/Embedding）→ 先依權限及生效版本過濾→ 檢索→ LLM 參考可信內容產生回答→ 引用來源。Embedding 是語意向量，不等於權限控制。來源文件可能有 Prompt Injection；不得讓檢索內容取代系統規則。
合成放款案例：貸款展期 SOP v1/v2，必須按有效日期、業務角色與文件版本檢索，回答附 SOP ID、版號、段落；查不到應表達不確定，不可憑空補寫正式規則。
Cloud SA Academy V1：Vue→Spring Boot Auth/RBAC→FastAPI RAG→Postgres Full-Text Search；之後評估 pgvector（需安裝擴充與模型）、local CPU embeddings；文件匯入用 Day25 的持久化 Job/Worker。正式成績及放款交易只能由授權的核心 API 修改。
雲端對照：AWS Bedrock Knowledge Bases 搭配 S3 Vectors/OpenSearch/Aurora 等向量儲存；S3 Vectors 偏語意搜尋，不能假設自動支援 Hybrid。Azure AI Search 支援關鍵字+向量 Hybrid；GCP Vertex AI RAG Engine 可做託管 RAG。功能、計費與權限整合非完全等價，零成本優先先用 NAS 既有環境。
