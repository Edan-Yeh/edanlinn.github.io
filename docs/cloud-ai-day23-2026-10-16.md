## 核心教學
服務 Health Check 通過，不代表業務邏輯、AI 回答或資料結果正確。區分 Application Deployment、Database/Schema 與 Business/AI Output 三個層次；Rollback Application ≠ Rollback Database ≠ 修正既有錯誤交易。

### AWS / Azure / GCP 對照
| AWS | Azure | GCP |
|---|---|---|
| ECS + Fargate | Container Apps | Cloud Run |
| Deployment Circuit Breaker | Multiple Revisions + Traffic Weights | Revision Tags + Traffic Migration |
| Service Auto Scaling | HTTP / KEDA Scaling | Request-based Scaling |

三者的回復、版本與擴縮模型並非完全等價。

## Q1｜單選（15 分）
銀行 Loan 計息 API 新版 Health Check 正常，但少數交易利息錯誤，同時仍有正常交易。哪種處置最能兼顧業務正確性與復原風險？

A. 只要容器健康就先不處理。  
B. 直接將整個正式資料庫還原到部署前。  
C. 先控制影響擴大、處理應用程式版本回復，再查核與補正受影響交易。  
D. 只重啟容器，假設已入帳的結果會自行修復。

- **使用者原答**：C
- **正解**：C
- **得分**：15/15
- **解析**：健康檢查不等於業務正確。需控制影響、恢復程式、找出受影響交易、依核准程序補正與對帳；不能預設整庫 PITR。

## Q2｜配對（20 分）
1. AWS ECS rolling deployment 失敗，想回到符合條件的先前完成部署。  
2. Azure Container Apps 希望新版 revision 先接收 10% 流量。  
3. GCP Cloud Run 希望先測試 tagged revision，再逐步導入正式流量。

A. Deployment Circuit Breaker  
B. Multiple revisions + traffic weights  
C. Revision tags + traffic migration

- **使用者原答**：1→C、2→A、3→B
- **正解**：1→A、2→B、3→C
- **得分**：0/20
- **解析**：ECS Circuit Breaker 用於偵測符合條件的失敗部署並可回復到先前成功部署；Azure Container Apps 的多 Revision 流量權重支援 10% Canary；Cloud Run 的 Revision Tag 可先測試特定版本再逐步遷移流量。這是本題的服務配對，非宣稱各雲僅支援該功能。

## Q3｜多選（20 分）
Cloud SA Academy 新增 AI Tutor，哪些措施應納入第一版？

A. 使用合成或經授權的去識別測試資料。  
B. 將未授權的企業內部資料直接提供給外部模型。  
C. 保留模型版本、Prompt 版本、Request ID 與人工覆核狀態。  
D. 讓 AI 自動覆寫正式學生成績，不需檢查。  
E. 將 FastAPI AI 推論與 Spring Boot 核心業務隔離，提供故障降級。  
F. 只檢查容器健康度，不驗證回答品質。

- **使用者原答**：A、C、E
- **正解**：A、C、E
- **得分**：20/20
- **解析**：資料治理、版本追蹤、隔離與降級是第一版關鍵；未授權資料不可外傳，AI 不得繞過正式評分規則，回答品質也需驗證。

## 實作｜Cloud SA Academy AI Tutor（45 分）
題目：以 Vue、Spring Boot、Postgres、NAS Docker 加上獨立 FastAPI AI Tutor 為前提，簡述：① Request Flow；② AI Timeout 降級；③ 正式成績保護；④ 新版錯誤時的回復與紀錄處理。

### 使用者原始作答（逐字保留）
> Vue 畫面>Spring Boot權限和帳號> Python FastAPI AI Tutor輔助驗證和降級
>
> 真的有資料異動 Postgres
>
> 新版發生錯誤時要先保留LOG資訊，先將版本回復到穩定版本，恢復完成在依據key值修復資料。

- **得分**：23/45
- **掌握**：前後端與 AI 微服務隔離的基本方向；正式資料存 Postgres；事故保留 Log、受控回復版本、按 Key 調查受影響資料。
- **待補強**：
  1. Request Flow 應包含身份驗證、Request ID、Spring Boot 呼叫 FastAPI、結果驗證、回傳 Vue；FastAPI 不應擁有正式成績的最終授權。
  2. Timeout/Failure：設定超時與錯誤邊界，回退固定教材/非 AI 練習，不讓 AI 故障拖垮登入與考試。
  3. Grade Integrity：AI 只能提供建議；正式成績寫入經 Spring Boot 權限與既有評分規則，資料庫最小權限、審核/稽核。
  4. Rollback：保留 Request ID、Model/Prompt/Deployment 版本與影響範圍；回復應用後仍需按核准程序補正受影響紀錄，避免重複寫入；不要直接整庫還原。

### SA 參考架構（補充教學，不是使用者原答）
Vue → Spring Boot（Auth/RBAC、Request ID、業務規則）→ FastAPI AI Tutor（推論、Timeout、品質檢查）→ Spring Boot 驗證回覆 → Vue。Postgres 由受控業務服務寫入正式成績；AI 失效時提供非 AI 教材與練習；日誌避免保存敏感原文並保留必要稽核資訊。
