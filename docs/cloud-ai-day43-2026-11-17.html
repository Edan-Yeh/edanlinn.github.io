② NET｜Next → Example → Try

Next：保留原本的單元測試，新增一支 MockMvc HTTP 層測試，驗證 GET /api/health 真正走 Spring MVC。

Example：在 src/test/java/dev/edan/bankingai/HealthControllerHttpTest.java 建立新檔。此範例以 Spring Boot 3.x / 4.x 對應的測試依賴與 import 為前提；若 IDE 無法解析 @AutoConfigureMockMvc，先確認 Spring Boot 版本及依賴，不要直接照抄錯誤 import。

package dev.edan.bankingai;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.test.web.servlet.MockMvc;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.*;

@SpringBootTest
@AutoConfigureMockMvc
class HealthControllerHttpTest {
    @Autowired MockMvc mockMvc;

    @Test
    void healthEndpointShouldReturn200AndJson() throws Exception {
        mockMvc.perform(get("/api/health"))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.status").value("UP"))
            .andExpect(jsonPath("$.service").value("banking-ai-platform"));
    }
}

Spring Boot 4 的 MockMvc 自動設定註解可能使用 org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc；以實際 pom.xml 與 IDE 可解析的套件為準。請先確認 spring-boot-starter-test，必要時檢查 Web MVC 測試依賴。

③ Debug｜Windows 11 真正排查

curl.exe -i http://localhost:8080/api/health
Get-NetTCPConnection -LocalPort 8080 -ErrorAction SilentlyContinue
# 查到 OwningProcess 後：
Get-Process -Id 12345

區分：404 代表有 HTTP 回應但路由不符；Connection refused 通常代表該位址/埠沒有服務接收；Port already in use 是應用啟動階段的埠衝突。MockMvc 不需真的開啟 8080 埠，故它與 curl.exe 測試的故障模式不同。
