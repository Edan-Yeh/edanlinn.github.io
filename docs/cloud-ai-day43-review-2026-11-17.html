二、架構題：原答與正解

題目：PostgreSQL 故障但 Spring Boot 仍回應，Liveness/Readiness 如何設計？部分功能依賴 DB 如何取捨？

你的答案（官方摘要）：Liveness 判斷應用是否正常運作，不應因非必要外部服務故障而重啟；Readiness 判斷能否接流量，依必要依賴檢查 PostgreSQL；部分功能依賴 DB 時依影響程度停止或降級。

建議完整答案：Liveness 代表應用程序是否需要重啟，不應把外部 DB 暫時失效直接當成程序死亡。Readiness 代表實例是否可以安全接收新流量；若 DB 是所有核心請求的必要依賴，DB 不可用時讓 Readiness 不就緒。若僅部分功能依賴 DB，可保留獨立功能並對受影響端點採明確降級/暫停，絕不繞過交易授權、資料一致性或必要驗證。監控故障、設定 timeout，恢復後做功能與一致性驗證。

面向你已掌握改善方案
Liveness定義正確說明避免無意義重啟
Readiness定義正確補上流量摘除與恢復條件
部分故障有降級意識區分可停用 AI 摘要與不可繞過一致性的交易查詢
復原未具體說明Timeout、監控、回復後 smoke test

金融情境：如果 PostgreSQL 是交易查詢必要依賴，該查詢應回明確不可用狀態；不依賴 DB 的靜態說明仍可提供。AI 文件摘要若依賴 DB 的 ACL/檢索，也不能在 DB 故障時改成未授權檢索。

三、Debug 題：原答與正解

題目：HTTP 404 與 8080 Port already in use 分別如何定位？

你的答案/實作（官方摘要）：實際驗證 HTTP 200、404、connection refused、Port 8080 already in use；用 PowerShell 找到占用 Port 的 Java 程序。
情境正確理解實際改善
404服務回了 HTTP，但路由找不到查 URL、@GetMapping、Controller package/component scan、context-path
Connection refused指定端點沒有接受 TCP 連線查應用啟動狀態、監聽位址與 Port
Port in use另一程序已綁定 8080查 OwningProcess 與程序，再決定關閉或換 Port
500伺服器內部處理失敗查 stack trace、例外處理、依賴故障
curl.exe -i http://localhost:8080/api/health
Get-NetTCPConnection -LocalPort 8080 -ErrorAction SilentlyContinue
# 將查到的 OwningProcess 數字代入
Get-Process -Id 12345
.\mvnw.cmd clean test

MockMvc 不需開 8080，因此 MockMvc 成功不代表網路埠一定可用；兩種測試互補。
