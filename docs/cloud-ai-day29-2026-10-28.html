AI Agent Tool Calling：模型能建議，但不能自行授權

2026/10/28（三）｜Cloud × AI｜20 分鐘｜滿分 100 分
延續 Day 28 的資料治理與正式成績權限邊界，這次改學 Agent 工具執行與安全架構；不重複考 pandas 去重題。

核心觀念｜Tool Call ≠ Authorized Action

想像 AI Tutor 回答：「幫我找出近七天最弱的三個主題。」模型可以提出呼叫 get_weak_topics 的請求，但不能憑模型的判斷直接連線資料庫。真正執行工具的程式必須再次檢查登入身分、RBAC、資料擁有權、參數與工具白名單。

Function Calling / Tool Calling 是讓模型提出「想用哪個工具、帶什麼參數」的機制；Tool Gateway 是你自己控制的執行邊界。即使模型輸出看似正確的 JSON，也不是授權證明。

白話比喻：模型像實習顧問提出作業建議；Spring Boot 像有權限的主管與系統關卡。主管必須查核，不能因為顧問說「我有權限」就直接放行。

Cloud SA Academy AI Tutor V1 流程

Vue（登入學生）
  → Spring Boot：驗證 JWT / RBAC / 學生資料擁有權
  → FastAPI：LLM 產生「建議工具呼叫」
  → Spring Boot Tool Gateway：驗證工具名稱、參數、權限
  → Postgres：執行允許的唯讀查詢
  → FastAPI：只接收必要、已過濾的結果
  → Spring Boot → Vue：顯示建議與可追溯資訊

安全界線：資料庫不直接暴露給模型；工具回傳內容與 RAG 檢索內容均視為不可信資料。寫入正式成績屬高風險業務動作，不能只靠模型建議，需由 Spring Boot 驗證授權、業務規則與明確核准，必要時使用 Idempotency Key 防止重試重複執行。逾時時應安全降級，不改動正式成績。
