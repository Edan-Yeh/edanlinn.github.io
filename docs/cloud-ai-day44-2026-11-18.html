今天要做什麼？

用原本的 banking-ai-platform，新增一個 MockMvc 404 測試，並練習區分 400、404、500、503。404 是路由不存在；400 是請求格式/參數不合規；500 是未預期伺服器錯誤；503 是服務暫時無法提供。這些狀態不能混用。

實作佔 70%｜架構 15%｜Debug 10%｜觀念 5%。請勿使用真實銀行/公司資料。

Next：開啟 VS Code，確認 src/test/java/dev/edan/bankingai/HealthControllerHttpTest.java 存在。先執行 git status 與 .\mvnw.cmd test 作為 baseline。

Example：沿用既有的 context、MockMvcBuilders、get、status 與 JUnit @Test imports，在既有測試 class 裡新增：

@Test
void unknownEndpointShouldReturn404() throws Exception {
    MockMvc mockMvc = MockMvcBuilders
        .webAppContextSetup(context)
        .build();

    mockMvc.perform(get("/api/health-typo"))
        .andExpect(status().isNotFound());
}

Debug 思考

如果測試回 200 而非 404，檢查是否有 catch-all mapping；如果是 compilation error，檢查 @Test imports、方法是否放在 class 裡及 context 變數是否存在；如果 Maven clean 因檔案鎖定失敗，先停止仍在執行的 Java/Spring Boot 程序，再重試。
