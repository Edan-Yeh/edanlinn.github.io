完整示範｜AI Tutor 逾時，如何設計不影響正式考試的降級？

情境：學生送出正式測驗後請求 AI 解說，但推論服務卡住。核心需求是成績先由既有規則保存，AI 解說可延遲或降級。

流程：Vue 提交測驗 → Spring Boot 驗證答案並依正式規則寫入 Postgres → 另行請求 FastAPI 產生解說 → 達到設定 Timeout 時顯示固定教材，不影響原本已保存的分數。

取捨：較短 Timeout 可降低等待但提高降級比例；較長 Timeout 增加完成機會卻拖慢體驗。應先用實測延遲決定門檻，而不是假設所有 AI 呼叫都能在 5 秒內完成。

驗證：模擬 FastAPI 無回應，檢查測驗分數不變、固定解說可用、Request ID 與 Fallback 原因可追蹤。

下一步練習：若 FastAPI 回傳格式錯誤而不是 Timeout，應如何驗證輸出並降級？請自行描述方案；此處不計入正式 Day 分數。

FOUNDATION / 01
01 / REQUEST FLOW

一個 AI Tutor 請求，實際經過哪些服務？

Vue 負責互動；Spring Boot 驗證身份、檢查權限並產生 Request ID；FastAPI 接收受控上下文，執行模型推論；Spring Boot 驗證回應再交給 Vue。Postgres 由授權業務流程寫入學習資料。

Vue → Spring Boot → FastAPI → Spring Boot → Vue

例子：學生問「什麼是 RTO？」；AI 可以解釋，但不能自行更改該學生的正式測驗成績。

02 / RELIABILITY

AI Timeout：為什麼要有降級模式？

推論比一般 API 更可能受模型載入、佇列與運算延遲影響。呼叫 AI 時設定 Timeout、限制重試與併發，逾時時返回固定教材或提示，避免核心考試功能被 AI 拖垮。

AI Timeout → Fallback → 固定教材

例子：學生正在考試，AI 解說超時；考試仍能提交，畫面改顯示預先準備的解析，而非卡住。

03 / DATA GOVERNANCE

AI 建議與正式成績必須分離

AI 的輸出是機率性結果，可能出錯。正式成績需由 Spring Boot 的既有評分規則與權限控管寫入 Postgres；AI 只能提供教學建議，不能直接擁有成績寫入權限。

AI Recommendation ≠ Grade Authority

例子：AI 認為學生答對，但標準答案規則判定答錯；正式成績以受控評分流程為準，必要時由教師審核。

04 / INCIDENT RESPONSE

Rollback 只修復版本，不會自動修復資料

先限制錯誤影響、記錄 Request ID／部署版本／模型版本／Prompt 版本，再回復穩定程式。已寫入的錯誤資料要先比對影響範圍，經核准後補正，不能直接整庫 PITR。

Contain → Rollback → Reconcile → Verify

例子：新版 AI 產生錯誤建議，回復 FastAPI 版本後，仍需檢查哪些學生看過錯誤內容。

延伸學習：LLM、Token、Embedding、RAG 與 Agent 有何不同？

LLM：透過訓練資料學習語言模式的模型，適合生成與推理，但可能產生不準確回答。

Token：模型處理文字的單位；輸入與輸出 Token 數會影響上下文長度、延遲與推論成本。

Embedding：把文字轉成向量表示，讓系統能比較語意相近程度，例如找到最相關的課程段落。

RAG：先檢索授權教材，再把檢索結果提供模型生成回答；仍需驗證來源、權限與引用品質。

Agent：模型在明確權限與工具規則下選擇下一步操作，例如查詢題庫；高風險寫入必須由業務系統驗證與授權。

具體範例：學生問「RPO 5 分鐘代表什麼？」→ 檢索 DR 教材 → 將段落與問題送入模型 → 回傳有來源的說明 → 記錄 Request ID 與教材版本；沒有授權就不讀取企業機密文件。
